# Lumia SSH 代码审查与 UI 重构方案

> 审查日期：2026-09-20  
> 审查基线：当前工作区（包含未提交修改与新增文件）  
> 对照文档：`01-DESIGN.md`、`02-UI-DESIGN.md`、`03-SYNC-PROTOCOL.md`、`04-TASKS.md`  
> 目标平台：Windows 10 Mobile 15063、Lumia 950、ARM32，兼顾横屏与 Continuum

---

## 1. 结论先行

当前工程的基础质量并不差：Core 单元测试、Native 测试、错误码一致性、文档检查、XAML 魔法数字检查和 App x64 Debug 构建均已通过；终端、同步、SFTP、转发等核心能力也已经形成较完整的代码骨架。

但当前状态还不适合直接进入“全页面换皮”。最需要先处理的是页面生命周期、异步任务和终端焦点这三类稳定性问题。它们会造成返回终端后重复刷新、页面无法释放、后台任务覆盖新页面状态、软键盘被意外关闭等现象。UI 观感差的根因也不只是配色，而是：

1. 有 token，但缺少完整、统一的组件层；
2. 主导航和底部菜单承载了太多功能，像开发工具面板而不是移动端产品；
3. 表单和列表大量直接使用平台默认控件，页面层级、留白和状态反馈不统一；
4. 中文字面量仍大量散落在 XAML/C# 中，视觉重构后再补本地化会造成二次返工；
5. 真机、软键盘、旋转、Continuum 和长时间运行验收尚未完成。

建议执行顺序为：**先稳定生命周期与终端输入，再建立组件库，然后逐页面改造，最后统一做本地化、无障碍和真机回归。**

### C-01 · P0 · 终端页事件订阅未释放

**证据**

- `src/SshTool.App/Views/TerminalPage.xaml.cs:128` 用匿名 lambda 订阅 `SessionInfo.PropertyChanged`；
- `src/SshTool.App/ViewModels/TerminalViewModel.cs:119` 用匿名 lambda 订阅 `_session.PropertyChanged`；
- `TerminalPage.OnNavigatedFrom` 只清理外观/省电相关事件，没有解除上述订阅。

**影响**

`SessionInfo` 和 SessionManager 的生命周期长于页面。匿名委托会持有旧 Page/ViewModel，导致页面无法回收；多次进入终端后还可能出现重复状态更新、重复 UI 调度，最终演变为卡顿或跨线程异常。

**处理方案**

1. 将匿名 lambda 改为命名处理器；
2. `TerminalViewModel` 实现明确的 `Detach`/`Dispose`；
3. `OnNavigatedFrom` 按订阅的反序解除，保证重复调用安全；
4. 增加“进入/退出终端 50 次后旧页面可回收、事件只触发一次”的回归测试或调试计数器。

### C-02 · P0 · 异步导航缺少失效保护

**证据**

`TerminalPage.OnNavigatedTo` 为 `async void`，在 `await ViewModel.LoadAsync(...)` 后继续绑定 Session 和事件。用户在加载期间返回时，旧页面仍可能在 await 完成后继续执行。HostEdit、Keys、SFTP、Settings 等页面也存在相似入口。

**影响**

- 已离开的页面继续订阅事件或显示错误；
- 旧请求的结果覆盖新导航状态；
- 页面关闭后仍操作 XAML 元素，出现 `RPC_E_WRONG_THREAD` 或对象已释放错误。

**处理方案**

- 页面保留导航世代号或 `CancellationTokenSource`；`OnNavigatedFrom` 立即取消；
- override/event 入口只负责调用可等待的私有 `Task` 方法；
- 每个 await 后检查页面是否仍为当前世代；
- 加载、错误提示、绑定动作必须共享同一生命周期。

### C-03 · P0 · 终端控件可能抢走软键盘焦点

**证据**

`01-DESIGN.md §7.5` 要求终端页所有可点击控件设置 `AllowFocusOnInteraction="False"`。目前 `TerminalView` 和 KeyBar 已按此处理，但 `TerminalPage.xaml` 的“更多”按钮以及 `TerminalWorkspace` 动态创建的关闭/分屏按钮没有统一约束。

**影响**

点击菜单或工作区操作后，焦点可能从隐藏输入哨兵转移，SIP 收起或后续键盘输入无法进入终端。这与“键盘弹出后看不到文字、输入无效”的故障属于同一条交互链路。

**处理方案**

- 建立 `TerminalIconButtonStyle`，统一设置触控尺寸、焦点行为和无障碍名；
- 所有终端页按钮、动态按钮都使用该样式；
- 菜单关闭后显式恢复哨兵焦点，但不要无条件反复拉起 SIP；
- 在 Lumia 上覆盖：打开菜单、切会话、分屏、旋转、SIP 收起/再次弹出。

**已确认的相关修复**

`TerminalView.xaml` 的 Win2D Canvas 已锚定左上角。SIP 缩小可视区域时，固定尺寸画布不再因默认居中而下移到键盘后方。该修改仍需 T09/U07 真机回归。

### C-04 · P1 · 异常处理过宽且经常静默失败

**证据**

App/Core C# 源码中有 168 处 `catch (Exception)`。部分用于 W10M 能力探测和清理是合理的，但终端工作区、外观应用、同步解锁/登录等路径也存在无上下文的吞错。`ObservableObject.RaiseOnUi` 在 UI 调度失败后改为当前线程直接发送 `PropertyChanged`，可能重新触发它原本试图规避的跨线程 XAML 问题。

**处理方案**

- 只捕获能被当前层正确恢复的异常，平台能力探测使用窄类型异常；
- 所有意外异常记录“模块 + 动作 + 异常类型”，日志中不得带密码、私钥、终端正文；
- UI dispatcher 失败且页面正在销毁时允许丢弃通知，不回退到后台线程直接操作 UI；
- 为连接、同步、SFTP、转发定义统一的用户可见错误映射，避免每页各写一套文案。

### C-05 · P1 · fire-and-forget 任务缺少统一观察

**证据**

App 中大量使用 `var ignore = XxxAsync()`，覆盖终端外观、分屏、新标签、主机列表刷新、SFTP 操作、分组管理、会话恢复等路径。

**影响**

调用方无法知道任务是否失败或是否仍属于当前页面；未由被调用方法内部完全处理的异常可能成为未观察异常，同类操作也可能并发覆盖。

**处理方案**

- 提供唯一的 `Forget(Task, context, logger)` 辅助方法，统一观察异常；
- 用户命令优先迁移到 `AsyncCommand`，执行期间管理 `CanExecute`；
- 刷新类操作使用“最后一次请求生效”或互斥门；
- 页面销毁时取消属于页面的任务，应用级恢复任务则由应用级 owner 持有。

### C-06 · P1 · 本地化覆盖不足，资源语言配置有警告

**证据**

- 69 个 XAML 文件中只有 8 个出现 `x:Uid`，共 40 个 `x:Uid`；
- 主页面、HostEdit、Settings、行菜单和多个对话框仍直接包含中文；
- `SshTool.App.csproj:12` 为 `DefaultLanguage=zh-CN`，构建持续产生 `PRI257`；
- Q04 尚未完成。

**影响**

英文模式会出现中英混排；UI 重构完成后再抽资源会再次触碰每个页面，并容易破坏布局。

**处理方案**

1. UI 重构时同步抽取可见文本，不再新增中文字面量；
2. 保证 `zh-CN`、`en-US` key 集合完全一致；
3. 校准项目、manifest、资源目录和 PRI 使用的文化标签大小写/默认语言；
4. 将 `PRI257` 视为 Q04/Q09 的阻断警告；
5. 为 125%～200% 文本缩放和较长英文标签保留布局空间。

### C-07 · P1 · 设置项在滑动过程中重复落盘和广播

**证据**

`SettingsRepository.Set` 无相等值短路，每次都会写 `LocalSettings` 并触发 `Changed`。Settings 页面中的字体、回滚行数、重连、超时和代理超时 Slider 都在 `ValueChanged` 中保存。

**影响**

拖动 Slider 会连续写本地设置并触发外观重算、同步脏标记或订阅方刷新，在 ARM32 手机上会形成可感知卡顿。

**处理方案**

- Repository 在验证后先与当前有效值比较，相同则不写、不广播；
- 外观可实时预览，但持久化使用 150～300 ms debounce 或拖动结束提交；
- 增加“同值 Set 不触发 Changed”的单测；
- 区分预览事件与持久化设置事件。

### C-08 · P1 · 核心类体积过大，UI 改动容易牵连业务

**证据**

| 文件 | 当前行数 | 建议拆分方向 |
|---|---:|---|
| `SyncCoordinator.cs` | 2001 | 拉取/合并/推送/重试/状态发布 |
| `SftpViewModel.cs` | 1407 | 浏览、文件操作、传输队列、展示状态 |
| `TerminalView.xaml.cs` | 1264 | 渲染、输入、选择、布局/缩放 |
| `SessionManager.cs` | 1132 | 打开、认证、重连、生命周期 |
| `SettingsViewModel.cs` | 1034 | 外观、连接、安全、同步分区 |
| `TerminalWorkspace.xaml.cs` | 1030 | 标签、窗格树、命令、视觉状态 |

**处理方案**

不要一次性重写。先补 characterization tests，再以现有 public contract 为边界提取内部协作者。UI 页面只依赖小型状态对象和命令，不直接承载连接、文件操作或同步流程。

### C-09 · P2 · 测试全绿，但测试与环境覆盖仍有空洞

**证据**

- Native 测试中的真实认证、Channel、KeepAlive、Agent、SFTP、Forwarding 集成场景依赖外部环境，本次未运行；
- `TunnelManagerTests` 存在 `.Result` 阻塞异步任务的 xUnit 分析器警告；
- Q01/Q02/Q03/Q05/Q08/Q10 仍待执行。

**处理方案**

- 将阻塞异步测试改为 `async Task` + `await`；
- 发布候选版本必须跑一次受控 SSH 服务器集成矩阵；
- Lumia 真机进行 30 分钟终端输出、反复进入退出、锁屏恢复、网络切换、SFTP 大文件和隧道持续运行测试；
- 自动通过和人工未验证必须在报告中分别列出，不能用“全绿”概括。

### C-10 · P2 · 任务状态与工作区实现存在时间差

当前工作区含大量未提交修改/新增文件；例如 F03/F05 对应的部分 SFTP、SOCKS/Forwarding 实现已经出现，但任务仍未勾选。这可能只是正常开发中状态，但会降低后续审查的可信度。

**处理方案**

- 每个任务收尾时同步更新任务状态、测试、设计决策和进度日志；
- UI 重构开始前建立一个可复现基线提交；
- 不在同一个提交中混合生命周期修复、视觉重构和协议修改；
- 每批改动都保留独立回滚点。

## 4. UI 现状诊断

### 4.1 可以保留的基础

- AMOLED 深色优先、终端第一、底部高频操作和状态可见，这四条产品原则正确；
- 4/8/12/16/24 间距、40 epx 触控目标、720 epx 宽屏断点可继续使用；
- 深色的黑底 + 深蓝表面 + 系统强调色方向适合 Lumia；
- 已有 Banner、StatusDot、KeyBar、HostRow、TabStrip 等组件雏形，无需推倒重来。

### 4.2 为什么现在看起来“像拼起来的”

1. `Themes/Controls.xaml` 主要只有文本与少量按钮样式，TextBox、ComboBox、ToggleSwitch、Pivot、列表行、卡片、图标按钮、分段选择器没有统一视觉规范；
2. 页面同时混用平台默认控件、定制颜色和零散局部样式，圆角、边框、按压态、选中态不成体系；
3. MainPage 的底部/溢出菜单包含设置、密钥、已知主机、片段、外观、关于、登录以及调试入口，一级信息架构过载；
4. Hosts 首页长期展示较大的快速连接表单，挤压主机列表；
5. HostEdit 与 Settings 使用长 Pivot + 密集表单，缺少分组摘要、渐进展开和稳定的保存位置；
6. UI 图标仍混有 `☰`、`⧉`、`▾/▸`、`↪`、`⌨` 等 Unicode 字符，与 MDL2 风格不一致；
7. 终端顶部 32 epx 信息条同时放两行文本和按钮，信息密度过高，窄屏/大字体下容易拥挤。

## 5. UI V2 方向：克制的移动终端工作台

关键词：**终端优先、OLED 友好、层级清晰、状态明确、操作克制。**

不引入 15063 不支持的 NavigationView、Acrylic、Reveal、InfoBar、TeachingTip 或系统 DropShadow。现代感通过字体层级、表面层级、留白、细边框、统一图标和简单状态动画实现。

### 5.1 视觉层级

建议把现有颜色 token 收敛成五层角色：

| 角色 | 用途 | 约束 |
|---|---|---|
| Canvas | 页面/终端背景 | 深色保持纯黑，减少 AMOLED 功耗 |
| Surface 1 | 列表行、普通卡片 | 与 Canvas 有可见但克制的明度差 |
| Surface 2 | 输入、选中、浮层 | 仅用于可交互或提升层级的区域 |
| Stroke | 分隔线、输入边框 | 默认低对比，聚焦时切 Accent |
| Semantic | Success/Warning/Danger/Info | 只表达状态，不作大面积装饰 |

原则：一个页面最多出现一个强强调操作；状态色只用于点、图标、细边或短标签，避免整张卡片高饱和。

### 5.2 字体与间距

- 保留 Caption 12、Body 15、Subtitle 18、Title 20、Header 28；
- 页面大标题只在一级页面使用，编辑页使用 20 epx 标题；
- 主文本最多两级，辅助信息统一用 Dim，不再出现多套灰色；
- 触控目标保持至少 40×40 epx，关键按钮建议 44×44；
- 页面内容使用 12 epx 手机边距、24 epx 宽屏边距；卡片内部固定 12/16 epx；
- 避免每个表单控件都独立占一大块垂直空间，标签、说明和错误采用固定顺序。

### 5.3 必须先建立的组件

| 组件 | 职责 | 必需状态 |
|---|---|---|
| `AppPageHeader` | 标题、返回、状态、1 个主操作 | normal/compact/wide |
| `SegmentTabs` | 替代视觉松散的二选一/三选一按钮 | normal/selected/disabled |
| `SurfaceCard` | 分组与表单容器 | normal/pressed/selected/error |
| `AppListRow` | 主图标、标题、副标题、状态、尾操作 | normal/pressed/selected/disabled |
| `IconButton` | 所有无文本操作 | normal/pressed/disabled，强制 AutomationName |
| `StatusPill` | 短状态，如“已连接”“离线” | neutral/success/warning/danger |
| `FormSection` | 标题、说明、内容、验证信息 | normal/error/readonly |
| `InlineBanner` | 页面级错误、离线、重试 | info/warning/error |
| `EmptyState` | 空列表的解释与单一主操作 | normal/offline/filtered |
| `BottomActionBar` | 手机端主操作与溢出操作 | normal/keyboard-visible |
| `TerminalIconButton` | 不抢输入焦点的终端操作 | normal/active/disabled |

组件样式统一放进 Theme ResourceDictionary；页面只组合组件，不手写颜色、圆角、Glyph 和控件模板。

改造点：

- 一级只保留主机、会话、隧道；密钥、片段、外观、已知主机归入“工具与设置”；
- 调试入口只在 Debug 构建的独立开发页出现；
- 快速连接默认收成底栏动作或一行可展开区域，不长期挤占列表；
- HostRow 使用统一领先图标/色标、状态点、主副标题和单一尾操作；
- 搜索、分组和排序放在同一工具区，空结果与真正无主机使用不同 EmptyState。

### 6.2 Terminal

目标：终端内容永远是视觉主体，SIP 出现后最后可见行和输入回显仍可见。

```text
┌ ● prod  deploy@10.0.0.5               ⋯ ┐  44 epx
├──────────────────────────────────────────┤
│                                          │
│              Terminal Canvas             │
│                                          │
│ $ █                                      │
├──────────────────────────────────────────┤
│ Esc  Ctrl  Alt  Tab  ↑  ↓  PgUp    ⌨     │  40 epx
└──────────────────────────────────────────┘
```

改造点：

- 顶栏调整到 40～44 epx；默认只显示一行“状态 + 名称 + 地址摘要”，横屏隐藏次要地址；
- 顶栏点击可展开详情，不在常态堆两行；
- 所有按钮使用 `TerminalIconButton`，不得抢哨兵焦点；
- 键条按钮使用同一 keycap 模板，粘滞/锁定状态用底边与颜色双重表达；
- 选区、字体缩放提示、断线/重连蒙层使用统一的 transient layer；
- SIP 高度变化只改变终端 viewport，不用平移固定画布；变化后立即重算行列并重绘；
- 宽屏 TabStrip、分屏按钮与手机信息条共享同一命令和状态模型。

### 6.3 SFTP

目标：文件浏览清楚，传输状态不遮挡当前目录。

- 顶部使用可横向滚动的面包屑，当前路径始终可见；
- 文件行固定为“类型图标 / 名称 / 大小与时间 / 更多”；
- 上传、新建文件夹作为主操作，删除/权限/重命名进入行菜单；
- 传输队列在手机上使用可展开的底部面板，在宽屏上使用右侧面板；
- 失败项必须显示原因和重试，完成项允许批量清除；
- 长文件名、英文、CJK 和不可打印名称分别测试截断与详情显示。

### 6.4 Host Edit / Settings / Sync

目标：把“长表单”改成可扫描的设置结构。

- Host Edit 分为基础连接、认证、终端、代理/跳板、高级五个 Section；
- 常用字段直接展示，高级项折叠；页面底部固定“测试连接 / 保存”；
- Settings 首页展示分组行和当前摘要，二级页再编辑具体值；
- Slider 同时提供当前数值和恢复默认，不在拖动中连续持久化；
- 登录/注册使用 `SegmentTabs`；窄屏全宽、宽屏限制最大宽度并居中；
- 同步状态、设备、历史和冲突页面共用同一状态卡、设备行与危险操作样式；
- 删除账号、清空云端、移除设备等危险操作必须二次确认并明确影响范围。

### 6.5 宽屏与 Continuum

- `< 720 epx`：单列、底部主操作、Overlay pane；
- `720～1023 epx`：主从双栏，详情在右侧；
- `≥ 1024 epx`：固定 320 epx 主列表，终端支持 TabStrip 与分屏；
- 只改变布局，不改变命令位置的语义；键盘快捷键和鼠标 hover 作为增强而非必要入口；
- 无真实 DropShadow 时用 1 epx Stroke + 表面明度差表达层级。

## 7. 交互、无障碍与本地化标准

### 7.1 交互

- 所有异步命令显示执行态并阻止重复提交；
- 可恢复错误必须给“重试”，不可恢复错误给“详情/修复建议”；
- 删除、断开、覆盖、清空使用动作动词，不使用含糊的“确定”；
- 导航返回必须先关闭 Flyout/Pane/Dialog，再离开页面；
- 动画只使用 120～200 ms 的透明度/位移 Storyboard，并尊重系统动画设置。

### 7.2 无障碍

- 每个图标按钮设置本地化 `AutomationProperties.Name`；
- 状态不能只靠颜色，同时有文字或形状；
- 键盘焦点顺序与视觉顺序一致；
- 200% 文本缩放下不裁掉主操作、错误信息和主机地址；
- 深浅主题下正文、次要文字、边框、错误态分别检查对比度；
- 终端颜色由用户主题控制，但应用控制层必须满足可读性。

### 7.3 本地化

- 页面可见文案全部进入 `.resw`；
- `x:Uid` 用稳定语义名，不带中文拼音或页面位置；
- 动态错误通过错误码映射到资源，不拼接难翻译的句子；
- 日期、大小、速度、端口和复数使用区域格式；
- 英文版重点检查按钮宽度、Pivot Header、Banner 和 ContentDialog。
