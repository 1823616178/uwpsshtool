## AI 分次编码工作流（每次会话都照做）

1. 读 `04-TASKS.md` 的「进度总览」与「进度日志」，找到**第一个依赖已全部勾选、自身未勾选**的任务。
   不要跳着做，不要一次做多个任务（除非任务里明确写了可合并）。
2. 读该任务「参考」一栏列出的设计章节与参考源码路径（鸿蒙端 / 桌面端）。
3. 实现 → 写测试 → 运行 `pwsh scripts/verify.ps1`（X06 之后可用；之前按任务里写的命令）。
4. 逐条核对该任务的「验收」清单。代码、自动测试与构建项全部满足后：
   - 把该任务行首 `- [ ]` 改成 `- [x]`；
   - 验收里标 📱/👤 的项是**渐进人工验收**，未验证时不要勾，把它们原样登记到 `04-TASKS.md` 末尾「真机验收待办」，但**不得阻塞任务完成或后续编码**；
   - Spike 的待测结果若可能改变架构，先采用文档中的保守兜底继续实现，并在待办中注明回测后可能调整；
   - 在「进度日志」追加一行：`日期 | 任务ID | commit 短哈希 | 说明/遗留问题`；
   - 更新「进度总览」表中对应里程碑的完成数。
5. `git commit`，提交信息格式：`feat(N03): SSH 会话状态机` / `fix(T05): ...` / `docs(X02): ...`。
6. 若实现中发现设计文档有错或需要变更：**先改设计文档并在进度日志里写明原因**，再改代码。
   禁止代码与文档长期不一致。

> 开发阶段不逐项打断用户做观感或真机确认；人工项按里程碑批量回归，发布前统一清账。

## 硬性约束（全部任务通用）

- **不改外部仓库**：`E:\code\ssh-tool`、`G:\code\ssh-tool-server`、`C:\Users\lx182\DevEcoStudioProjects\ssh_client_ohos` 只读参考，一行不改。
- **同步格式零偏差**：云端文档必须严格是桌面端 `SyncDocumentV1`（对端是 `z.strictObject`，多一个键整份拒绝）。
  以 `E:\code\ssh-tool\src\shared\sync-schemas.ts` 与 `src\main\sync\*.ts` 为唯一权威，详见 `03-SYNC-PROTOCOL.md`。
- **本机专有数据不上云、下行不得清空**：分组归属、外观、片段、known_hosts、跳板、初始命令、环境变量、终端类型、tmux 附着、隧道 autoStart 等。
- **禁止魔法数字与硬编码颜色**：XAML 与 C# 一律引用 `Themes/Tokens.xaml` 资源（见 `02-UI-DESIGN.md §2`）。
- **日志脱敏**：不记录密码、密码短语、私钥、token、同步密码、恢复密钥、请求体、同步明文与密文。
- **Windows 10 Mobile 兼容**：`TargetPlatformMinVersion = 10.0.15063.0`；任何高于 15063 的 API 必须 `ApiInformation` 守卫并有降级路径；C# 语言版本 7.3；共享库只能是 `netstandard1.4` 及以下。
